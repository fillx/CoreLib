# Process: Roadmap & MVP Goals

**Роль:** Product + PM-first  
*(Product приносит список MVP-фич из GDD, PM-first режет и структурирует.  
Все решения строго опираются на `vision.md`, `goals.md` и `gdd.md`.)*

## Задача
Разбить MVP на последовательные итерации, каждая ≤ 1 недели и каждая даёт демонстрируемый инкремент.  
Сформировать Slim-roadmap (черновые вертикальные срезы) и Fat-roadmap (чистовую карту с приоритетами и сроками).  
Поддерживать roadmap «живым» документом, который корректируется после каждой итерации.

## Важные правила
- [ ] Если `vision.md`, `goals.md` или `gdd.md` отсутствуют → процесс стоп, PM требует документы.
- [ ] Если в этих файлах размыто → процесс стоп, PM требует доуточнения.
- [ ] В roadmap можно заносить только фичи из `gdd.md`.
- [ ] Каждая итерация должна вести к цели из `goals.md`. Если связи нет → переносим в backlog «позже».
- [ ] Итерация без демо запрещена.
- [ ] Roadmap ведётся в двух слоях: Slim (черновой) и Fat (чистовой).
- [ ] После каждой итерации разработки — обязательная коррекция Slim, потом обновление Fat.
- [ ] Нельзя двигаться по Fat-roadmap без актуального Slim.

## Два слоя Roadmap
- **Slim:** черновая карта вертикальных срезов.
    - Каждая итерация ≤ 1 недели.
    - Каждая итерация = демо, даже если на кубиках.
    - Цель — максимально быстро показать путь к MVP.
- **Fat:** развёрнутая карта.
    - Итерации могут быть агрегированы (например, объединяем 2–3 slim-среза).
    - Указываются приоритеты и сроки.
    - Цель — контроль сроков и коммуникация с бизнес-целями.

## Шаги
1. Product берёт список MVP-фич из `gdd.md`.
2. PM-first проверяет связь каждой фичи с целями в `goals.md`.
3. Формируем Slim-roadmap: делим крупные фичи на микро-срезы (каждый ≤ недели, с демо).
4. Из Slim формируем Fat-roadmap: объединяем итерации, добавляем сроки и приоритеты.
5. Фиксируем оба слоя в `/docsAi/product/roadmap.md`.

## Чек-лист (Go/No-Go)
- [ ] В начале roadmap есть ссылка на `vision.md` и `goals.md`.
- [ ] Slim-roadmap: 3–6 микро-итераций, каждая ≤ недели, каждая = демо.
- [ ] Fat-roadmap: агрегированные итерации, с приоритетами и сроками.
- [ ] Каждая итерация (Slim/Fat) связана с целями в `goals.md`.
- [ ] Roadmap укладывает весь MVP из `gdd.md`.
- [ ] Roadmap обновлён и структурирован.

## Поведение PM-first
- Жёстко проверяет: «Эта итерация ведёт к метрике из goals?». Если нет → выброс.
- Делит большие фичи на вертикальные срезы.
- Спорит по приоритетам: любое «красивое, но не MVP» уходит в backlog.
- Следит за циклом: после каждой итерации разработки → пересмотр Slim → обновление Fat.
- Стопит процесс при размытости или если Slim отсутствует.

## Проверка закрытия этапа
- Slim-roadmap можно объяснить за 1 минуту: «И1 = X (демо), И2 = Y (демо)…».
- Fat-roadmap понятно показывает приоритеты и сроки.
- Каждая итерация связана с целью в `goals.md`.
- Нет пустых или «для красоты» итераций.
- Суммарно MVP укладывается в 4–6 недель.
- `roadmap.md` содержит обе версии: Slim (микро-срезы) и Fat (чистовой план).

## Коррекция Roadmap
- Roadmap пересматривается:
    - После каждой итерации (вместе с Retro).
    - При выявлении «жирных» или лишних фич.
    - Если цели/метрики изменились.
- Коррекция всегда: сначала Slim → потом обновляем Fat.

## Работа с новыми идеями
- Новые идеи фиксируются в backlog (связь с метрикой обязательна).
- Текущие итерации доводятся до конца, даже если появилась новая идея.
- Пересмотр и приоритизация идей происходит только на Retro/коррекции Roadmap.
- Допустимо расширять жанр новыми механиками только после проверки core loop.
- Без связи с `vision.md` и `goals.md` идея не может попасть в roadmap.
